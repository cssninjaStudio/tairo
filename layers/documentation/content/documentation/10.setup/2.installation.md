title: Install and run the project
---

Tairo needs you to install the dependencies defined in all `package.json` from the different pacakges. 

To do so, use the following command:

```bash
pnpm install
```

You can check which directories are consired as package in the `pnpm-workspace.yaml` configuration file.


Now you can start the project using the following command:

```bash
pnpm dev
```

Running this command will start the development server from `.app` folder and open the demo app in your browser. You can now start editing the files and see the changes in real time.


:::doc-message{type="muted" icon="ph:info"}
You will see the Tairo Welcome page, see how to [build your first page](#) guide to replace it.
:::

Once you are done, you can stop the development server by pressing `Ctrl + C` (or `Cmd + C` on macOS) in your terminal. To deploy the project for production, use the `pnpm build` command. This will build the project in the `.app/dist` folder.

:::doc-message{type="primary" icon="simple-icons:discord"}
Join on our [Discord server](https://go.cssninja/discord) to get help from the community.
:::

title: Run the full demo
---
The source of this demo is separated from Tairo source, 
allowing you to simply remove related folder in order to have a clean project.

The Tairo demo is split into differents layers: 

```bash
├── .demo # This is the entry point of the demo (demo app layer)
├── layers
│   ├── documentation # Contains nuxt/content related features
│   └── landing # Contains marketing related features
```

To start the project from the demo instead of the app folder, run this command:

```bash
pnpm demo:dev
```

:::doc-message{type="muted" icon="ph:info"}
Check the `scripts` section of the `package.json` file to know what you can run with `pnpm`.
:::

By default the `documentation` layer is not enabled, it's a heavy layer due to usage of [nuxt-component-meta](https://github.com/nuxtlabs/nuxt-component-meta) module which allows us to generate up to date components documentation directly from sources.

You can copy the `.demo/.env.example` to `.demo/.env` to enable it, as other additionnal features described in file. *Note that this architecture can be used to create kill switch feature flag*
